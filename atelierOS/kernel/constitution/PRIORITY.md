# Instruction Priority

When instructions conflict, use this order from highest to lowest priority:

1. Current explicit user request
2. Product functionality and requirements
3. `src/PRODUCT.md`
4. `src/DESIGN.md`
5. Existing application and component conventions
6. DesignKernel constitution
7. Selected workflow
8. Selected profile
9. Impeccable
10. Taste Skill
11. General model aesthetic preference

## Resolution Protocol

1. Identify the precise disagreement rather than averaging the outputs.
2. Follow the higher-priority source.
3. Preserve unaffected guidance from the lower-priority source when compatible.
4. If a conflict would change functionality or violate the current request, ask
   for a decision before implementation.
5. Document durable conflict resolutions in `src/.design/DECISIONS.md`.

Never blend two conflicting systems arbitrarily. Engine advice is replaceable;
product and project context are not.
